## Correctness
| Finding | Severity | Why It Matters |
|---|---|---|
| All five bail-out paths in `RewriteMySqlBindMarkers` (GlobalIndex guard QuarryGenerator.cs:1041-1048, slot range/duplicate check :1067-1071, active-set mismatch :1073-1085, pagination-rank/coverage checks :1106-1109, merge contradiction :1102) silently leave binding at identity; on any chain whose text order genuinely diverges, that identity fallback IS the #303 bug shipped silently at runtime | Medium | The fallbacks are safe only in the sense of preserving pre-#303 behavior; nothing distinguishes "validated identity" from "validation failed, possibly misbinding" — no diagnostic, no log, no test hook |
| Pagination markers are emitted with the running clause-level `paramIndex` (SqlAssembler.cs:1099-1107), which excludes projection parameters (explicitly noted at SqlAssembler.cs:388-395), while `RewriteMySqlBindMarkers` expects limit/offset at slots `paramCount`/`paramCount+1` (QuarryGenerator.cs:1026-1027). A MySQL chain combining parameterized window-function projection args with parameterized Take/Skip emits a colliding/under-counted marker index, always fails validation, and silently keeps identity binding — i.e., the #303-class swap for that combination (text order [proj..., where, limit] vs add order [where, proj..., limit]) remains live | Medium | This is exactly the chain shape the new mechanism exists to fix; passing `pag.LimitParamIndex`/`OffsetParamIndex` (the true global slots, ChainAnalyzer.cs:1293) to the marker formatter instead of the running count would make it work |
| Marker stripping happens inside the interceptor output action (QuarryGenerator.cs:658-669) by mutating shared `AssembledPlan` instances, but the manifest is an independent `RegisterImplementationSourceOutput` over the same `perFileGroups` instances (QuarryGenerator.cs:144-146 vs 162-172); nothing guarantees Roslyn runs the interceptor action before the manifest action | Medium | The "markers must never leak into manifests" invariant rests on undocumented cross-output execution ordering; the pre-existing pattern (collection tokens) had a cosmetic failure mode, marker leakage is corrupted manifest SQL |
| The `whereShiftExpr != null && bindOrder == null` ParameterName guard (src/Quarry.Generator/CodeGen/CarrierEmitter.cs:759-767) is a no-op: `bindOrder` is non-null only on MySQL, where both branches emit the identical literal `ParameterName = "?";` (`EmitParamNameExpr` returns `"\"?\""` and `FormatParamName` returns `"?"`, CarrierEmitter.cs:1584-1609). The comment's "slot-keyed literal names" / shift-collision rationale describes behavior that does not exist | Low | Dead condition plus an incorrect comment (echoed in llm.md) will mislead future maintainers about how MySQL parameter naming works; the plan's own claim of "@pN, driver-ignored" names on MySQL is also wrong |
| Verified non-issue: a stored `MySqlBindOrder` is provably a complete permutation of `0..paramCount-1` (range + duplicate + `tail != paramCount` coverage checks, QuarryGenerator.cs:1067-1109) before `CarrierEmitter` indexes with it, the re-run of `RewriteMySqlBindMarkers` on an already-rewritten cached plan is idempotent (no markers ⇒ early return preserving the prior ranking), and the emitter's if-block open/close logic keyed on `BitIndex` change (CarrierEmitter.cs:697-726) is order-agnostic, correctly emitting split blocks for permuted same-bit runs | Low | Non-obvious safety properties that the change's correctness hinges on; confirmed by code inspection so the classification pass need not re-derive them |

## Security
| Finding | Severity | Why It Matters |
|---|---|---|
| Developer-authored constant strings are inlined into variant SQL as quoted literals (SqlExprRenderer.cs:308-313); `RewriteAndExtract` (src/Quarry.Generator/IR/MySqlBindMarkers.cs:126-166) does not skip quoted regions, so a source literal containing `{__Q<digits>__}` is rewritten to `?` inside the string — validation then fails and identity binding ships, but the corrupted SQL (an extra positional placeholder inside what was literal text) ships too, unconditionally. No end-user/runtime injection vector exists (runtime values are always DbParameters; markers exist only at generation time), and no new dependencies were added | Low | Silent generation-time SQL corruption from marker-shaped developer text where pre-#303 the text passed through verbatim; exotic trigger, developer-controlled only, but the rewrite-even-when-invalid policy makes it unrecoverable |
