## Fix Verification

**Verdict: QUALIFIED YES.** The core mechanism is sound and end-to-end correct for the reproducer shape and for every surface it was execution-tested on (wrap, window-fn projection params, projection-params + parameterized pagination, single-bit conditional × wrap, collection expansion × wrap). Two defects qualify the verdict: (1) the QRY048 fallback warning — the remediation of pass-1 findings #1/#6 — is **inert**: the descriptor was never registered in `s_deferredDescriptors`, so every QRY048 the orchestrator emits is silently dropped at reporting time; (2) `TryMergeTextOrder`'s greedy anchor-insertion produces **false contradictions** for chains with ≥2 independent conditional parameterized clauses, so those chains fall back to identity binding — which, combined with (1), means a wrap chain with two if-gated parameterized `Where` clauses still ships the #303 misbind with **zero diagnostics**. Both are narrow, mechanical fixes; neither invalidates the architecture.

## Correctness

| Finding | Severity | Why It Matters |
|---|---|---|
| QRY048 can never surface: `DiagnosticDescriptors.MySqlBindOrderFallback` is missing from the `s_deferredDescriptors` registration dictionary (QuarryGenerator.cs:804-832) that maps deferred diagnostic IDs to descriptors. The dictionary's own comment (QuarryGenerator.cs:826-828) documents this exact trap ("Without these entries ... the diagnostics would be silently dropped"). Verified: the only references to QRY048/`MySqlBindOrderFallback` in non-test source are the descriptor declaration (DiagnosticDescriptors.cs:697) and the orchestrator emission (PipelineOrchestrator.cs:107) — there is no other reporting path. It also voids the accepted-risk rationale for pass-1 security finding #11 ("loud once #1 lands") |
| `TryMergeTextOrder` reports false contradictions for chains with ≥2 independent conditional parameterized clauses. Masks are processed in ascending numeric order (PipelineOrchestrator.cs:587-588), so singleton variants precede the combined variant. Trace for two if-gated parameterized `Where` clauses (masks 0-3, per-variant text orders `[]`,`[0]`,`[1]`,`[0,1]`): mask 1 seeds `master=[0]`; mask 2's `[1]` has no anchor, inserts at front → `[1,0]`; mask 3's `[0,1]` then finds 0 at pos 1, 1 at pos 0 → `return false` (PipelineOrchestrator.cs:714-719). Same failure with an unconditional anchor param (`[0]`,`[0,1]`,`[0,2]`,`[0,1,2]` → `[0,2,1]` vs `[0,1,2]` → false) and for 2 conditional `Set()` params on Update. Since renderers traverse clauses in fixed structural order, a *true* contradiction is impossible — every "contradictory placeholder order" failure this code can produce is a merge-algorithm artifact. Consequence: those chains fall back to identity. For flat chains identity is correct (spurious warning only, and currently invisible per the finding above); for a **wrap chain with ≥2 independent conditional parameterized WHERE terms plus a parameterized hoisted ORDER BY, the original #303 misbind still ships — with no diagnostic**. Corpus verification: no MySQL chain with ≥2 distinct conditional parameterized clauses exists in quarry-manifest.mysql.md, so no test observes this. Fix directions: process variants in descending active-count order (the all-bits mask contains every independent slot and correctly seeds the master), or a proper topological merge with GlobalIndex tiebreak as planned | High | The canonical conditional-query pattern (multiple independent if-gated filters) is the very shape the mask-variant machinery exists for; on MySQL it either produces warning noise (once QRY048 surfaces) or, combined with the wrap, an unreported live misbind — i.e., #303 is not fully fixed |
| Zero-marker variants bypass validation: `if (failure != null || textOrder.Count == 0) continue;` (PipelineOrchestrator.cs:618-619) treats a marker-free variant as "nothing to validate". If a current or future MySQL render path emits bare `?` for an active parameter in *every* variant (i.e., a path that misses the `EmitMySqlBindMarkers` flag entirely), `master` stays null and the method returns success at :666-667 — the "a parameter never appears in any SQL variant" check at :679 is unreachable. Partial misses are caught by the active-set check, but a whole-surface miss degrades to silent identity rather than QRY048 | Med | The mechanism's declared value ("this check alone would have caught #303 at compile time") only holds if a surface that never emits markers is loud; distinguishing "variant legitimately has no active params" (mask math) from "variant has active params but no markers" is a cheap strengthening |
| Verified non-issue: `AppendPagination` using inner-plan-relative `LimitParamIndex` would mis-number placeholders if a *rebased inner render* (CTE `paramBaseOffset`, set-op operand) carried parameterized pagination — but lambda-inner plans are constructed with `pagination: null` (ChainAnalyzer.cs:3004), set-op operands take the same path, and a direct-form CTE inner chain with a parameterized limit was already unbindable pre-change (the pagination param is in neither `InnerParameters` nor the outer carrier). No reachable regression; literal limits are unaffected | Low | Non-obvious; the one theoretical caller shape where the finding-#7 remediation's "true global slot" premise breaks is provably absent |
| Verified non-issue: emitter safety under permutation — `MySqlBindOrder` is a validated complete permutation of `0..paramCount-1` (range+dup+coverage checks) before `bindOrder[k]` indexing; conditional block open/close keyed on consecutive `BitIndex` change handles split same-bit runs; `__bindShift` is consumed only as a post-loop sum (order-independent) and MySQL `ParameterName` is the constant `"?"` (CarrierEmitter.cs:1588, 1605), so mid-loop shift values are irrelevant on the only dialect that reorders; pagination slots are verified trailing and keep the bind-after-loop structure; re-running the post-pass on an already-rewritten cached plan is a no-op that preserves the stored ranking | Low | These are the properties pass 2 was asked to hunt regressions in; confirmed by inspection so classification need not re-derive |
