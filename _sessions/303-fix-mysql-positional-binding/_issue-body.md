## Description

A CTE chain that combines a captured parameter in the inner `With<T>(...)` lambda with a captured parameter in an outer clause (`Where` after `FromCte<T>()`) fails generation with **QRY037**: the carrier declares the outer parameter's field (`P1`) but no clause interceptor body assigns it. QRY037 is the generator's own self-check ("Generator defect: ... The corresponding SQL parameter would silently bind default(T). Please file an issue."), so the build fails loudly rather than misbinding — but the chain shape is unusable.

```csharp
decimal threshold = 100.00m;
int minId = 2;
var rows = await db.With<Order>(orders => orders.Where(o => o.Total > threshold))
    .FromCte<Order>()
    .Where(o => o.OrderId >= minId)   // captured outer param — its carrier field is never assigned
    .Select(o => (o.OrderId, o.Total))
    .ExecuteFetchAllAsync();
```

## Location

- Error surfaces at the terminal call site; the emitted carrier is generated by `CarrierEmitter`, the missing assignment belongs to the outer `Where` clause interceptor body.
- QRY037 detection: `DiagnosticDescriptors.CarrierParameterFieldUnassigned`.
- Likely root area: CTE parameter rebasing in `ChainAnalyzer` (inner params are prepended to the outer parameter list with sequential `GlobalIndex`) vs. the clause-interceptor parameter-assignment emission, which appears not to account for the rebase offset when the outer clause's params come after inner-lambda params.

## Diagnostics

```
error QRY037: Generator defect: carrier 'Chain_10' declares parameter field 'P1' but no clause
interceptor body assigns it. The corresponding SQL parameter would silently bind default(T).
Please file an issue.
```

## What Has Been Tried

- Reproduced on master (c149cfb) with a minimal generator-driver test (MySQL dialect context) — **pre-existing**, not introduced by #304 (whose changes touch bind ordering only, not parameter-field assignment).
- Inner-param-only CTE chains work (assignment + binding verified by a real MySQL execution test added in #304: `ParameterizedCteFilter_OnMySQL_BindsInnerParamsBeforeOuter`).
- Outer-literal workaround: replacing the outer captured param with a literal generates and executes correctly.

## Gathered Information

- Inner lambda params rebase onto the outer slot range (inner = slot 0..k, outer following), and the WITH clause renders first, so SQL-text order is chain order — bind ordering is not the problem; the outer clause's interceptor simply never assigns its carrier field.
- Dialect-independent: the assignment gap is in shared emission, not a dialect branch (observed on MySQL; nothing dialect-specific in the path).

## Suggested Approach

Trace how clause-interceptor bodies map lambda captures to carrier `P{n}` fields for chains with a `CteInfo`/parameter offset: the outer clause's `LocalIndex`→`GlobalIndex` mapping most likely needs the CTE rebase offset applied (mirroring what `SqlAssembler` does with `paramBaseOffset` for rendering). Add a generation test asserting the outer param's assignment exists, then a cross-dialect execution test for inner+outer parameterized CTE chains.
